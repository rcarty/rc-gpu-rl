Training an AI drone pilot in WebGPU

Thousands of simulated quadrotors learning to fly to a target in 3D, trained on your GPU in this page. Every generation, each drone flies a slightly different copy of the same small neural network, and the network moves towards the copies that did best. The orange drone flies the current network. Drag to look around.

I made this as a first step into mixing graphics with AI. I wanted to understand one of the fundamentals, which is how a network can learn a task by trial and error.

This browser doesn't support WebGPU, so the demo can't run here. Recent Chrome, Edge, Safari and Firefox all support it.

The environment

Each drone is a rigid quadrotor with four motors. It sees the target, its velocity, which way is up and its spin, all in its own body frame, and sets the thrust of each motor. Thrust points along the body, so to move sideways it has to lean, and to stop it has to lean the other way.

An episode is six seconds and the target moves halfway through. Every drone gets its own mass and its own gusts, so the network has to cope with all of them. Drones that leave the arena are out for the rest of the episode.

Training

Training uses evolution strategies (Salimans et al., 2017). The network has 548 weights. Each generation adds random noise to them for every pair of drones, one with the noise added and one with it subtracted, so both see the same start and the same gusts. Scores are turned into ranks, and the ranked noise gives an estimate of which way to move the weights. Adam takes the step.

There's no backpropagation anywhere. Every pass is a forward pass, which is why the whole thing fits in a few compute shaders.

The controls

Noise is how far each copy strays from the current network, and the learning rate is how far the network moves each generation. Turn either up far enough and training falls apart. More drones give a steadier estimate per generation.

Gusts and mass variation apply in training and when flying, and are fixed for each drone when it starts. The motor slider only applies when you fly the policy. It weakens one motor on every drone, which the network never saw in training.

On the GPU

One thread per drone steps the physics and runs the network, with the weights for every drone in one buffer. The scores are ranked with the key-value radix sort from the sorting demo, and an update pass uses one workgroup per weight to sum the ranked noise and apply Adam.

The noise is never stored. Both passes regenerate it from a hash of the generation, the pair and the weight index. Nothing comes back to the CPU except the scores for the chart.
